\section*{Abstract}
\addcontentsline{toc}{section}{Abstract}
The Students Results and Grade Management System is a standalone desktop application for maintaining student records, subjects, examination marks, grades, and class results. It is implemented using Java and standard Java Swing components. The application stores data in local UTF-8 CSV files, so it works without a database or internet connection. It validates input, prevents duplicate records, calculates totals and percentages, identifies PASS, FAIL, and INCOMPLETE results, assigns grades, and produces individual and class-level result views. The implementation follows a simple layered design with model, repository, service, user-interface, and utility packages. The executed Java test runner reported 50 passed tests and 0 failed tests, including grade boundaries, input validation, result calculation, duplicate detection, CSV loading, and merit-list ordering.

\textbf{Keywords}: Java Swing, student records, grade management, CSV persistence, result calculation, input validation.

\section{Introduction}
Manual result preparation can cause calculation errors, duplicate records, incomplete entries, and delays when searching for a student's academic information. This project provides a local desktop alternative for a faculty member or academic administrator. The system is designed for demonstration and course-end evaluation, not as a networked institutional ERP system.

The application is intentionally dependency-free. It runs locally on a compatible Java Development Kit and uses standard Java APIs for collections, file handling, validation, date-independent calculations, and Swing-based GUI development.

\section{Objectives and Scope}
The main objectives are to:
\begin{itemize}
    \item register, search, update, and delete student records;
    \item configure subjects, maximum marks, and minimum passing marks;
    \item enter and update subject-wise examination marks;
    \item calculate totals, maximum marks, averages, percentages, grades, and result status;
    \item identify failed and missing subjects clearly;
    \item generate individual report cards and a class merit list;
    \item preserve data between sessions using CSV files; and
    \item demonstrate object-oriented programming, collections, validation, exception handling, GUI programming, and file handling.
\end{itemize}

The application is limited to local single-computer use. It does not provide authentication, a database server, cloud synchronization, web access, or PDF export from inside the application.

\section{System Architecture}
The system uses a simple layered architecture. Model classes represent students, subjects, marks, and calculated results. Repository classes load and save CSV data. Service classes perform grade and result calculations. Swing panels provide the presentation layer, while utility classes hold constants and reusable validation logic.

\section{Functional Implementation}
\subsection{Student and Subject Management}
A student record contains a unique student ID, full name, roll number, department, semester, and optional email address. The system rejects empty mandatory fields, duplicate IDs, and duplicate roll numbers. Subject records contain a unique code, name, maximum marks, and minimum passing marks. The default demonstration data contains five subjects, each with a maximum of 100 and a minimum passing mark of 35.

\subsection{Marks and Result Calculation}
The marks screen allows a registered student and subject to be selected before a score is entered. A score cannot be negative or greater than the configured maximum. Saving an existing student-subject pair updates that record instead of creating a duplicate.

For a completed set of required subjects, the calculation rules are:
\begin{align*}
\text{Total Marks} &= \sum \text{valid subject marks}\\
\text{Percentage} &= \frac{\text{Total Marks}}{\text{Maximum Possible Marks}} \times 100\\
\text{Average} &= \frac{\text{Total Marks}}{\text{Number of Subjects}}
\end{align*}

A student is PASS only when every required subject has a mark and meets its passing threshold. A missing required mark produces INCOMPLETE. A completed result with any failed subject produces FAIL.

\subsection{Grading and Merit List}
The grading scale is A+ for 90--100, A for 80--89.99, B for 70--79.99, C for 60--69.99, D for 50--59.99, E for 35--49.99, and F below 35. Completed results are sorted by percentage in descending order. Incomplete results are shown separately or after completed results and are not ranked as completed results.

\subsection{User Interface}
The Swing interface provides dashboard statistics, workspace navigation, forms, tables, validation messages, confirmation dialogs, and individual result views. The current visual system uses a warm paper background, ink-black navigation, a restrained vermilion action color, and a warm yellow highlight. The design is an editorial desktop interpretation inspired by the reference direction of h2a.lu, while remaining a local Java Swing application.

\section{Conclusion}
The Students Results and Grade Management System provides a concise, functional Java desktop solution for academic record and result management. It separates data storage, business calculations, validation, and Swing presentation so the project remains understandable for a course-end demonstration. The system meets its core objectives and was verified by 50 passing automated tests. Future work could include authentication, database storage, multi-user access, and export facilities, but those features are outside the current implementation.
